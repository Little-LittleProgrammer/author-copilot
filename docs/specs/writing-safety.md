# P0.1 创作安全与发布收口

## 目标与范围

在现有本地写作与受控 AI 修改基础上，保护作者正文、提供可核验的作品备份，并建立可重复执行的发布检查。原生 Agent 的整轮保留/恢复继续沿用现有权限和快照机制。

## 自动保存与草稿恢复

- 正文停止编辑 1.2 秒后自动保存，继续使用内容哈希基线与原子替换；不自动创建 Git 提交。
- 输入法组合输入、AI 修改、版本操作、恢复草稿审阅或正文冲突期间暂停自动保存。
- 每次正文编辑通过 typed preload IPC 提交草稿，主进程将草稿原子写入当前账号的 `runtime/registry/drafts/<projectId>`；不向 AI 工具开放该目录。
- 草稿包含作品 ID、正文相对路径、基线 SHA-256、内容、修订 ID 和主进程生成的时间。仅作品所属标签页可以操作。
- 删除使用修订 ID 条件检查；较早保存完成后的清理不能删除较新的输入。
- 作品打开时列出可恢复草稿；已删除或移动来源的草稿仍可查看和复制。作者可以稍后处理或明确删除。
- 恢复界面并列显示正文与草稿，提示来源变化。恢复时重新核对界面展示的正文版本，变化后要求刷新。
- 恢复只把草稿载入编辑器；作者明确保存前保持磁盘正文，暂停自动保存。
- 写盘失败时显示保护失败，保留编辑器内容及上次成功的草稿；不声称尚未收到主进程写入确认的最后输入已安全持久化。

## 作品备份与恢复

- 编辑器作品标题旁提供备份；作家中心提供“从备份恢复”。未结束的 AI 审阅必须先保留或恢复。
- 备份包括作品目录内的正文、结构元数据、创作资产、Skill、Git 历史/分支，以及独立运行目录中的正文恢复草稿。
- 备份不包含账户凭据、余额、全局配置、聊天记录、写作统计、知识索引或 AI 运行时快照；这是一份作品备份，不是整个账号镜像。AI 未决快照不在备份内，因此未决任务会阻断备份。
- 每次备份创建唯一文件夹。复制先写临时目录，校验源与副本后才发布完成目录；失败清理临时目录。
- 清单记录文件相对路径、大小及 SHA-256。源在复制中变化、恢复时内容缺失或变化均失败，不注册半成品。
- 目标不能位于任何当前已注册作品中；拒绝符号链接、硬链接、特殊文件、Git 锁或外部对象链接。
- 上限为 10,000 个文件、总文件内容 512 MB、单文件 128 MB、清单 64 MB。超限报告失败，不截断内容。
- 恢复自动读取作品类型，生成新作品身份，保留历史提交和分支并重设恢复草稿的作品 ID；原作品和备份不被覆盖。
- 恢复保留故事内容和 Skill，但清理 Git 可执行 Hook 与外部配置，应用重新生成受保护的运行权限配置。

## AI 故障

- 流必须正常终止才标记成功，断流保留已收到的文本并显示失败。
- HTTP 错误不由 SDK 自动重试。作者可重新编辑原问题，再明确发送；不因网络恢复自动消费额度。
- 对话写入立即提交给主进程排序，防止刷新丢失渲染进程队列内的部分回答或终态；保存任务固定最初账号目录。
- 正常退出等待草稿、正文、对话与 AI 任务收尾。

## 发布验收

- 常规 `pnpm verify` 验证静态检查、契约、存储、模拟网络故障、构建与 Electron 流程。
- `pnpm --filter @author-copilot/desktop release:qualify-live` 是显式付费模型验收命令，需要通过环境提供 `AUTHOR_COPILOT_LIVE_AI_KEY`、`AUTHOR_COPILOT_LIVE_AI_MODEL`，兼容服务可设置 HTTPS 的 `AUTHOR_COPILOT_LIVE_AI_URL`。使用合成内容，不使用作者稿件。缺少配置失败；普通测试跳过此专项。
- `pnpm --filter @author-copilot/desktop release:materials` 从已安装的桌面生产依赖生成 SBOM、第三方声明与待审核项；打包时包含这些材料。它不能代替许可证审核或二进制组成核对。
- 四架构 CI 增加源程序完整 E2E；保留打包程序 smoke 与 Git/FTS5 检查。这不等于已完成每个签名安装包的完整 Agent/恢复、安装升级和卸载验收。
- 手动触发 `Desktop package matrix` 并选择 signed 时，要求签名证书和应用许可证；macOS 开启公证并检查 `codesign`/`spctl`，Windows 检查 Authenticode。材料生成、CI 配置或未签名开发包均不代表签名发布通过。
