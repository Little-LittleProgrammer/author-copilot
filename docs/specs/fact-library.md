# 作者可修订的事实库

状态：已实现首版（2026-11-07）。承接单篇章节摘要，作为长篇知识基础。

工作区实现更新（2026-11-09）：按[工作区与 Skill 规范](ai-workspaces-and-skills.md)，资料已存入本书创作资产文件，界面与 Skill 共用；下文保留该能力的来源、作者确认及状态语义。原生工具可修订已有内容，不能伪造来源或直接新增作者已确认事实。无需旧资料迁移。

## 用户流程

在“创作资料”点击“提取候选事实”，选择一篇已保存章节或场景。选中摘要或事实时默认定位其来源正文，提取仍读取当前已保存正文，不把摘要、其他资料或未保存编辑当作事实证据。

一次生成至多 12 条独立候选，每条包含标题和最多 4,000 字符的事实内容。提示模型保留时间、视角、否定和不确定性，不将人物猜测视为客观事实；没有可靠事实时允许返回空列表。模型准确性仍由作者审阅。

作者逐条编辑、勾选确认或舍弃；编辑会清除该条确认，需重新核对。点击“保存已确认事实”只保存勾选条目，未选择的候选保留在窗口继续审阅。全部保存或舍弃后可关闭。失败、取消或超时保留上一批候选；重新生成或关闭有候选的窗口需确认放弃。候选仅在内存，不提供崩溃恢复。

“事实库”筛选展示已保存事实，支持编辑和删除。手动编辑保留原始来源快照，不自动覆盖作者修订；重新提取产生新候选，不自动替换旧事实。跨批次相似事实由作者取舍，首版不自动合并或判定冲突。

## 来源与 AI 引用

主进程读取正文后记录项目内相对路径、SHA-256 和读取时间，候选 ID 也由主进程生成。模型工具只接受事实标题与内容，拒绝额外字段。生成期间正文改变不刷新候选的来源哈希。

选中事实、窗口聚焦或手动检查时，主进程通过资料 ID 查找来源并读取当前已保存正文：一致表示上次检查匹配；变化提示复核；缺失提示来源已删除或移动；访问错误提示无法检查。检查不实时轮询，不包含未保存编辑，移动后不猜测新路径。作者可以打开来源正文。来源匹配不等于事实内容已经被自动验证。

已确认事实复用资料引用入口供 Ask／Agent 显式选择，引用快照携带完整事实内容、来源与资料修订时间。每轮最多 6 条资料，事实最多 4,000 字符，因此当前轮无需截断单条事实。历史轮次仍遵守既有缩短策略。提示模型保留作者措辞、引用来源路径，并显式指出与正文的冲突；来源快照不保证正文仍然一致。

## 契约、持久化和边界

- `CreativeNoteKind` 增加 `fact`，必须具有来源；其他普通资料仍不能携带来源。
- `creative-notes:generate` 增加事实提取，严格要求唯一正文来源、无资料引用、无更新目标。复用供应商选择、计费、作品并发锁、取消和超时；不自动重试收费请求。
- 返回草稿与候选列表使用严格的独立响应形状；模型输出列表最多 12 条，每条最多 200 字符标题和 4,000 字符正文。来源正文最多 120,000 字符，超限或空白在模型调用前拒绝。
- `creative-notes:confirm-facts` 接受作者确认的候选并原子保存整批。稳定 ID 保证相同批次重试不重复入库；已有 ID 的内容或来源不同则整批冲突，不覆盖后续修订。超出资料总容量 500 条时整批失败。
- 原 `creative-notes:summary-status` 统一为 `creative-notes:source-status`，摘要与事实共用；契约、preload、主进程和调用者一起更新。
- IPC 检查可信主框架、参数及当前作品归属，来源状态只接受作品和资料 ID；主进程复用既有正文路径和符号链接限制，不暴露绝对路径或凭证。
- 事实与其他资料共用本书 `创作资产/资料.md`，参与作品 Git 版本；内容、来源和修订元数据保存在同一文件中。正文导出仍排除资产，不提供旧资料迁移或跨设备同步。

全书批量提取、人物与世界观实体、事实关系、时间线、自动冲突检查、自动上下文注入、语义检索和完整长期记忆仍属后续能力。

## 验收重点

1. 未勾选或舍弃的候选不持久化；编辑需重新确认，保存部分候选后其余仍可审阅。
2. 整批保存原子且重试幂等；冲突、容量和非法输入不部分落盘。
3. 生成后正文变化不伪造新来源；手动修订、重载和来源丢失均保留事实及快照。
4. 事实可以选入 Ask／Agent，快照包含来源，未保存候选不进入 AI 引用。
5. 中英文与窄窗口下可以完成提取、编辑、确认、舍弃、来源检查和引用。
