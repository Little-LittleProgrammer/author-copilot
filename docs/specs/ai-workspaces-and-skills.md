# 账号全局工作区、作品工作区与 Skill

- 更新：2026-11-09。
- 状态：已实现首版。全局助手只读，Shell 关闭；实现及验证边界见[交付记录](../reports/2026-11-09-ai-workspaces-and-skills.md)。
- 关联：[业务需求](REQ-001/业务需求/index.md)、[当前路线图](../roadmap.md)、[Agent 恢复约束](../adr/0001-dirty-repository-agent-rollback.md)。

## 目标与场景

AI 能力以账号全局工作区和单部作品工作区组织，两种入口分别拥有明确的文件权限、对话上下文和 Skill 范围。

首页的全局 AI 助手服务当前登录账号，可回答全局创作问题、定位某部作品、查询该作品剧情，以及分析两部或多部作品的关联。全局 `.claude` 承载这一入口的技能与配置，也提供可供作品场景使用的通用技能。

作品内的 AI 助手服务当前作品，例如读取大纲、查询人物设定、回顾剧情、执行写作技巧、续写、检查一致性与维护创作资产。作品级 `.claude` 承载本书专属技能与配置。作品助手的文件权限限定在当前作品，需要跨作品处理时切换到全局助手。

当前项目尚未上线。本设计按新结构实施，不增加旧作品、旧配置或旧资料的迁移与兼容分支。

## 工作区与目录

下图对应首版目录。身份为 local 或平台账号 UUID；作品目录使用作品 UUID。小说继续使用卷/章目录，剧本使用幕/场目录。人物、世界观等独立资产目录可按后续 Skill 需要扩展。

```text
用户数据目录/
├── accounts/<accountId>/
│   ├── workspace/                    # 全局助手 cwd
│   │   ├── .claude/
│   │   │   ├── settings.json
│   │   │   ├── hooks/
│   │   │   └── skills/
│   │   │       ├── locate-work/SKILL.md
│   │   │       ├── compare-works/SKILL.md
│   │   │       └── writing-techniques/SKILL.md
│   │   ├── CLAUDE.md                 # 全局场景说明、作品定位和资产约定
│   │   └── projects/<projectId>/     # 作品助手 cwd
│   │       ├── .claude/
│   │       │   ├── settings.json
│   │       │   ├── hooks/
│   │       │   └── skills/
│   │       │       ├── read-outline/SKILL.md
│   │       │       └── continue-story/SKILL.md
│   │       ├── CLAUDE.md             # 本书说明、资产位置和创作约定
│   │       ├── author-copilot.json
│   │       ├── 创作资产/
│   │       │   └── 资料.md             # 各类资料及来源元数据的唯一持久化来源
│   │       ├── 第一卷/第一章/01-正文.md # 小说；剧本使用幕/场
│   │       └── .git/                # 启用作品版本管理时
│   └── runtime/                     # 会话、索引、快照等应用运行数据
└── credentials/                     # 应用管理的加密凭据
```

正文、作品专属 Skill 和创作资产均存于作品文件夹。作品 ID 是目录身份；标题用于展示，改名不移动文件夹，同名作品互不覆盖。新建与导入统一使用应用管理的作品目录，导入保留源文件。

账号工作区之间隔离。免登录模式使用独立的本地身份命名空间，不默认取得任意已登录账号的数据。账号切换必须结束或取消原身份的任务，并切换作品清单、对话、Skill、索引及运行数据的命名空间。

密钥、应用内部状态和可再生索引不进入 AI 创作工作区。全局会话与各作品会话分别保存；不得因为共享技能而自动共享对话历史。

## Skill 与创作资产

大纲读取、资料定位、剧情查询、写作方法、续写和一致性检查都以 Skill 描述能力。Skill 可包含 `SKILL.md`、参考材料及必要资源；具体大纲、正文、人物和来源记录保存在作品创作资产中，由技能按需读取、引用与维护。

例如“读取本书大纲”技能应说明大纲在哪里、如何关联章节、遇到缺失或过期来源时如何处理；“按本书风格续写”技能应说明适用场景、所需资产、写作步骤及审阅要求。大纲等资产的使用流程属于技能设计，不为每类资产继续新增一套 AI 专属文件工具。

| 场景 | Skill 范围 | 文件访问范围 | 典型任务 |
| --- | --- | --- | --- |
| 首页全局助手 | 当前账号全局 Skill；按任务使用目标作品的相关技能 | 当前账号工作区；按请求定位作品 | 查询某书剧情、比较两书关联、通用创作建议 |
| 作品助手 | 适用于作品场景的全局通用 Skill＋本书 Skill | 当前作品目录 | 读取大纲、续写、维护人物与摘要 |

全局 Skill 应声明适用场景；仅适用于跨作品任务的技能不进入作品助手的可用集合。作品专属技能不自动成为其他作品的技能。全局助手需要本书知识时，通过作品定位及目标技能按需加载，不启动即加载所有作品的技能和资产。

首版显式只加载 cwd 的 project 配置源，在创建任务快照前把适用的全局通用技能投射到作品内。本书同名技能优先；未编辑的投射同步全局更新，已被本书修改的投射成为本书覆盖版本。指纹保存在私有 runtime 中，并已用真实 SDK 验证覆盖行为。不能依赖 Claude 沿父目录扫描产生继承关系。技能加载范围不扩大文件访问范围，Skill 或 `CLAUDE.md` 中的文字也不授予额外权限。

## 全局助手与作品助手的权限

应用主进程根据当前身份及入口确定工作目录与策略，Renderer 或模型不能自行指定其他账号、任意磁盘根目录或额外工作目录。

- 全局助手的 `cwd` 为当前账号创作工作区，能够读取其中的作品正文和创作资产；回答应带作品身份与来源，区分不同作品的设定和作者确认内容。
- 作品助手的 `cwd` 为本书目录，拒绝访问父级全局目录、兄弟作品、其他账号及应用内部数据。通用 Skill 由应用按所需范围加载，不通过开放父目录来取得它们。
- 跨作品查询和比较默认只读。涉及资产或正文修改时，明确列出目标作品及变更，按作品进入审阅、版本和恢复流程；不得因全局入口具有更广的读取范围而隐式修改多书。
- Claude 使用 Read、Glob、Grep、Write、Edit 等原生工具，目标实现不再提供自写的 `mcp__author_copilot__*` 文件读写工具。
- Settings 定义工具和目录策略，Hooks 在执行前检查真实路径、权限及受保护文件，执行后通知应用刷新。权限策略必须覆盖符号链接、目录跳转、未知工具及额外目录扩展。
- 权限 Settings 与安全 Hook 由应用维护并保护，模型不能编辑、删除、替换或关闭；作品 Skill 和创作资产可以进入作者可审阅的维护流程。导入文件夹内的配置、Hook 和技能脚本在应用检查前不得自动执行。
- 全局 `.claude` 位于应用管理的账号工作区，不默认使用个人 `~/.claude`。`CLAUDE_CONFIG_DIR` 指向账号私有 `runtime/claude`，创作配置通过当前工作区的 project 配置源加载；不再使用每任务临时配置目录。自动祖先 `CLAUDE.md` 加载被排除，应用只注入当前工作区说明。

Settings 与 Hooks 约束原生文件工具；任意 Shell 子进程还需要操作系统沙箱。允许 Bash／PowerShell 时必须验证沙箱确实生效并禁止无沙箱重试；平台不支持或沙箱不可用时禁用 Shell。Hook 程序本身由应用信任与约束，不因为它位于 `.claude` 就自动获得安全保证。

安全 Hook 启动失败、异常、超时或返回非法结果时，涉及的操作必须阻止。具体 Settings 字段及 Hook 失败策略要在锁定的 Claude 运行版本上验证，不能只根据最新文档推定可用。

## 资产维护、索引与版本

应用界面与 Claude 读取、维护同一份作品文件。大纲、人物、世界观、摘要及事实库的正文和必需元数据应有唯一持久化来源，不继续在独立 JSON 与作品文件之间双写。具体来源记录和结构化元数据格式在资产契约中确定。

章节摘要与事实仍保留作者确认、来源相对路径、内容哈希、捕获时间和来源状态语义。技能指导生成、读取与维护；技能执行本身不能替代作者确认或事实证据。读取已有文件不能恢复未保存编辑器草稿，也不能把旧摘要当作当前正文的事实证明。

作品 Skill、创作资产和正文纳入作品版本及变更审阅范围，凭据、缓存及任务临时数据排除在外。运行策略由应用负责校验，不能随一次作品版本恢复而悄然降级。人物与世界观目录的出现不代表结构化实体、关系图或自动一致性能力已经实现。

原生工具通过 PreToolUse 在执行前记录 before-image、预期 after-image 和索引状态，并在 PostToolUse 核验结果，复用持久 mutation ledger。已有文件必须先读取，写入前重新校验基线；取消或后置 Hook 缺失时也保留写前记录并核验。文件与索引刷新、审阅、版本保留和恢复已接通；仅观察写后结果仍不构成修改归属证明。

读写流程需覆盖写入前记录、写入后归属、失败或中断、作者并发编辑及跨作品部分成功。未证明对应写入路径具备可靠恢复能力前，不开放该路径；不能默默退化为整目录覆盖、`reset --hard` 或把用户改动当成 AI 改动。

## 实施边界

| 项目 | 首版实现 |
| --- | --- |
| 身份与作品目录 | `accounts/<identity>/workspace/projects/<projectId>/`；免登录身份为 `local` |
| 助手入口 | 首页全局助手只读查询当前账号作品，作品助手可审阅改稿 |
| 配置与 Skill | 全局和本书 `.claude`；显式作用域、投射和本书覆盖；引擎数据在私有 runtime |
| 文件工具 | 原生 Read、Glob、Grep、Write、Edit、Skill；不再提供自写 MCP 文件工具 |
| 创作资料 | 本书 `创作资产/资料.md`，界面与技能共享，保留来源及确认语义 |
| 修改恢复 | 原生写入前记录和写后核验；支持取消、审阅、保留和恢复 |
| 暂不开放 | Shell、NotebookEdit、子 Agent、外部 MCP、插件、可执行 Skill Hook；全局跨作品写入 |

首版不增加旧作品或旧资料迁移。全局跨作品修改、更多可执行工具、资产实体关系和四架构生产资格验证仍需独立实现与验收；现有历史交付记录保留当时结论。

## 验收

1. 新建及导入作品生成独立工作区，存在本书 `.claude`；全局工作区具有独立 `.claude`。无需用户选择作品保存目录，不增加旧作品迁移。
2. 全局助手可以定位某书、回答其剧情问题及比较两书关联，输出可区分的作品与来源；不能读取其他身份或应用凭据。
3. 作品助手可使用通用与本书技能，不能调用其他作品专属技能或读取其他作品；全局通用技能不会带来父目录访问权限。
4. 用真实 SDK 验证技能加载与冲突规则、原生工具权限、绝对路径、`../`、符号链接、额外目录扩展及受保护配置修改；更换作品或账号后不串用原上下文和任务权限，返回原作品仍可读取其独立保存的历史。
5. 权限 Hook 缺失、异常、超时和输出错误均阻止相应操作。导入不执行来源自带的 Hook 或脚本。
6. Shell 沙箱不可用时不执行 Shell；可用时实际尝试越界读写及无沙箱重试，确认均被拒绝。
7. 界面和技能共享创作资产，修改后刷新正文、资料及索引；来源与确认状态正确，失败不产生部分双写。
8. 原生工具修改可审阅、保留、取消和恢复；覆盖新建、编辑、删除、崩溃及并发作者改动。跨作品失败不回滚其他作品的用户改动。
