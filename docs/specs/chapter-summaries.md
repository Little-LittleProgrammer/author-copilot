# 章节摘要

状态：已实现（2026-11-07）。长篇知识基础的第一步。

工作区实现更新（2026-11-09）：按[工作区与 Skill 规范](ai-workspaces-and-skills.md)，资料已存入本书创作资产文件，界面与 Skill 共用；下文保留该能力的来源、作者确认及状态语义。原生工具可修订已有内容，不能伪造来源或直接新增作者已确认事实。无需旧资料迁移。

## 目标与流程

作者从一篇已保存的章节或场景提炼可复用资料。入口为“创作资料 → 生成章节摘要”，也可在 AI 生成资料中选择该类型。选择正文后，无需填写额外要求即可生成，默认覆盖主要事件、人物变化、时间地点和未解决线索。可以追加要求、编辑标题和内容，确认后才保存。

摘要独立于正文；生成不改写文稿、不建立 Git 版本。已保存摘要可以手动编辑、删除、按类型筛选或选入 Ask/Agent 引用。选中摘要后再次生成，默认更新原摘要并展示差异；仍可改存新资料。保留既有时间戳冲突、失败重试、取消、超时和未保存保护。

## 来源与可信度

- 一次只总结一篇已保存文稿。不发送其他资料作为事实来源，更新时的旧摘要仅作为编辑基线。提示模型遵守原文事实、标注未知，不能用生成提示代替事实准确性验证。
- 主进程记录实际读取正文的相对路径、SHA-256 和读取时间。模型不能返回或选择这些字段；工具输出只允许标题和内容。
- 确认保存可保留已过期的草稿；来源状态会表明生成后正文的变化。不会把新正文的哈希写到旧草稿上，也不会自动重写作者修订过的摘要。
- 选择摘要、窗口聚焦或点击“检查来源状态”时读取当前已保存正文：相同哈希为“上次检查一致”，不同为“可能过期”，文件不存在为“来源已删除或移动”。权限、路径安全或其他读取错误报告暂时无法检查。状态不实时轮询，不检查未保存的编辑器内容。
- 打开来源复用现有文稿导航。移动或重命名不会自动猜测来源；作者重新选择当前文稿并生成。
- 手动修订摘要保留来源快照，表示所依据的正文版本，不表示模型内容全部正确或作者从未修改。AI 引用携带该来源元数据，并提示引用前检查来源状态；不自动刷新旧对话快照。

## 契约与持久化

`CreativeNoteKind` 新增 `summary`，此类型必须具有 `source: { relativePath, contentHash, capturedAt }`；其他类型不能携带来源。生成请求必须恰有一个 `documentPaths`，`noteIds` 为空。正文及更新目标合计最多 120,000 个 UTF-16 字符，不截断，空白章在模型调用前拒绝。其余生成限制、供应商选择与收费传输复用现有服务。

增加类型化 `creative-notes:source-status` IPC，输入仅允许 `projectId`、`noteId`。主进程验证可信主框架和当前作品归属，从主进程资料中查找来源，再复用 `ProjectService.readDocument` 的目录、文件类型和符号链接限制；读取错误不泄露绝对路径。

摘要存入本书 `创作资产/资料.md`，与其他资料一起原子保存并参与作品 Git 版本；正文导出仍排除创作资产，草稿仅保留在内存。本次不提供旧资料迁移或跨设备同步。

## 验收

1. 无当前正文也可选择已保存章节，空章和非法来源在模型调用前拒绝。
2. 草稿生成不持久化；作者编辑后确认保存，来源和内容重载后仍在。
3. 生成期间正文变化仍记录原读取版本；来源状态可提示过期，移动/删除不会丢失摘要。
4. 手动编辑保留来源；重新生成审阅后更新来源；保存冲突不覆盖他人版本。
5. 中英文及窄窗口可操作，来源可定位，AI 引用保留来源元数据。

单篇可修订事实库已在[事实库首版](fact-library.md)中实现；全书批处理、自动事实维护、人物与世界观实体、语义检索及一致性检查仍是后续工作。
