# TXT 与 Word 导入

## 使用方式

“导入作品”中可选择 Markdown 文件夹，或通过“选择 TXT / Word 文件”选择单个 `.txt`、`.docx`、`.doc` 文件。选择小说或剧本类型，查看目录与前 2,000 字符的正文预览，确认后选择新作品的存放目录。

文件导入创建一份新作品，不修改原文件。默认启用“TXT / Word 自动拆章”，按识别到的卷、章节建立文稿；关闭拆章或未识别到章节时，小说正文写入 `第一卷/第一章/01-正文.md`，剧本正文写入 `第一幕/01-第一场.md`。已有同名作品不会被覆盖。

## 正则拆章规则

- 逐行匹配独立标题：`第一章`、`第12节`、`第十三回`、序章、楔子、引子、前言、尾声、终章、后记、番外，以及 `Chapter 1` / `Chapter IV`、Prologue、Epilogue。兼容全角数字和 Markdown 标题前缀。
- `第…卷/部/篇`、Volume / Book / Part 建立分组；剧本另识别幕 / Act 和场 / Scene。
- 保守匹配短标题行（原始行不超过 100 字符，去除前缀后的标题不超过 80 字符），包含句号、分号或引号的行不匹配。特殊格式可能不命中，确认前应检查目录预览。
- 标题、空行、正文均保留；开头未归属章节的文字作为前言，卷标题与卷前文字保留在该卷首篇文稿。所有生成文稿按顺序拼接等于解析后的原始正文。
- 卷和章节名称附加顺序编号，并清理路径特殊字符，确保重复标题不覆盖、阅读顺序不依赖标题中的数字排序。
- 目录预览与编辑器隐藏四位排序前缀。小说章节仅包含 `01-正文.md` 时，合并展示为可直接打开的章节，编辑器使用章节名；卷保留展开结构，多文稿章节或独立命名的文稿保留原层级。已有导入作品重新打开即可使用，无需重新导入或迁移文件。
- 章节合并展示后，读取、保存及 AI 上下文使用正文文件路径；重命名和删除使用章节目录路径。重命名保留排序前缀，并同步当前文稿与 AI 上下文路径。
- 最多生成 2,000 篇文稿，超出会报错，不静默截断。拆章规则为内置正则，当前不提供自定义正则输入。
- 切换拆章开关会清除旧文件预览，重新选择文件预览后才能确认。

- TXT：支持 UTF-8（含 BOM）、带 BOM 的 UTF-16 LE/BE；没有 UTF-8 BOM 且 UTF-8 解码失败时尝试 GB18030。
- Word：提取文字正文和段落，不保留图片、页眉页脚、批注及复杂版式；不需要安装 Office。
- 输入文件上限 20 MiB，转换后的 UTF-8 正文上限 10 MiB；空正文、损坏/受保护文档会报错。
- 预览后源文件发生变化时，确认导入会被拒绝，需重新选择并预览。切换作品类型也会清除旧预览。
- Markdown 文件夹的原地导入、复制导入保持可用。

## 实现

新增 `word-extractor` 运行依赖及类型声明。Word 解析使用独立 Node Worker，设定 15 秒超时及 128 MiB V8 old-generation 限制；Worker 是独立构建入口。TXT 使用 Node TextDecoder 解码。

预览只读源文件，完整正文、不可变的拆章计划与原始字节 SHA-256 保存在主进程。跨进程契约仅返回显示名、格式、文本片段、字符数和预览令牌，不返回绝对路径。令牌绑定请求窗口，15 分钟后过期；重新预览时清理该窗口旧令牌。文件导入禁止原地模式。

确认时重新核对源文件 SHA-256，按照预览使用的同一拆章计划写入所有文稿，复用作品创建的 staging、发布和注册回滚流程；初始文稿路径及重名检查在发布前完成。新增 `invalid_import` 错误码，Renderer 按错误原因提供中英文提示。
