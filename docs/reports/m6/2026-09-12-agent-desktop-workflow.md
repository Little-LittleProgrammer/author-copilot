# M6：单次授权 Agent 桌面流程

- 日期：2026-09-12
- 基线：REQ-001 已批准的技术方案、实施计划 M6、ADR-0001
- 状态：桌面功能已接通；本机自动化验证结果见下文，四架构发布验收仍待完成

## 用户流程

1. 进入本地工作区，在 AI 设置中保存 Anthropic API Key。
2. 打开作品的 AI 对话页，填写 Agent 任务要求，查看作品范围和时限，勾选单次授权并启动。
3. Main 复核登记目录，必要时初始化 Git（不提交已有草稿），持久化任务前快照，然后授予本次任务的 capability。
4. 运行中显示进度，可取消；编辑、结构修改、恢复和版本操作互斥。切换作品不会取消任务，关闭所属标签会撤权并取消。
5. 结束后显示摘要、错误、工具拒绝次数和任务前/当前内容对照。失败、超时、取消均保留已发生的修改，不自动重跑。
6. 可继续局部编辑；保存后刷新审阅，再保留并创建结果版本，或恢复到任务前。恢复冲突逐项展示，保留冲突文件。
7. 重启后从持久化快照恢复审阅，原 capability 不恢复。未完成的任务必须先保留或恢复，才能启动新任务。

## 实现约束

- Renderer 只使用共享契约和类型化 Preload：`agent:start/state/cancel/retain`，`agent:event`；恢复沿用 `task-recovery:restore`。
- API Key 由 Main 从系统加密存储读取，不进入启动请求或 Renderer 响应。
- 本次授权覆盖当前项目中的 Markdown 读取、搜索、新建与编辑；禁用内置 Shell、Web、任意 MCP、插件、设置和子 Agent。
- SDK 原生二进制从 lockfile 固定的对应平台包解析，安装包配置为 ASAR 外部可执行文件。任务配置目录独立、会话不持久化。
- UI 提供 1/5/15 分钟时限，默认 5 分钟，SDK 最多 32 轮。授权过期、取消和终态均撤权；写操作在最终替换前再校验，终态等待写队列清空。
- Main 的正常退出等待任务清理。独立进程守护不接收 API Key，在 Main 管道意外断开时终止 SDK 进程组；Windows 使用绝对路径的 `taskkill /T /F`。
- 运行进度不传输工具参数、正文、密钥或绝对路径。结果摘要和恢复正文属于用户私有任务数据，不写入诊断日志。
- Agent 写入或恢复后取消可能读取旧内容的索引构建，将已有知识索引标记为过期并要求重建，避免把旧索引宣称为当前内容。

## 结果版本与 dirty repository

保留操作将结果写入 `refs/author-copilot/tasks/<taskId>`。先使用私有临时索引生成任务前基线树，再生成当前受影响文件的结果树；结果提交的父提交是这份基线。两个对象仅在用户确认保留后创建。

正常分支的 HEAD、暂存区和工作区保持不变。无关文件的未提交修改不进入结果版本；同一文件的暂存/未暂存内容也不被重置或自动提交到原分支。应用版本列表会显示结果引用，diff 只展示相对于任务前的修改。结果引用不自动推送远端。

审阅摘要包含内容哈希；保留时在读取前后复核，文件变化会要求重新审阅。Git 故障保留正文、快照和持久化的版本异常状态；重试只重试创建版本。引用写入成功而客户端丢失响应时，可按任务 ID 幂等确认。

审阅预览每侧每文件最多 100,000 字符，总计 400,000 字符，截短时明确提示；保留版本保存完整文件内容。快照沿用单文件 5 MiB、任务 50 MiB 的预算。
